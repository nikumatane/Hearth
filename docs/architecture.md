# Hearth 架构决策

## 目标

在不迁移现有 Windows 游戏安装目录的前提下，提供更新、启停、状态监控和
Palworld 1.0 配置编辑能力。面板自身保持低资源占用，并把高风险系统操作约束在
明确的白名单内。

## 采用方案

生产环境部署为一个 Go 二进制：

1. Vue 前端在构建阶段输出静态资源。
2. 静态资源嵌入 Go 二进制。
3. Go 提供管理员/成员认证、查询 API、登录与参数审计、任务编排和游戏适配器。
4. 面板通过 Windows 启动计划任务以 `SYSTEM` 运行。
5. 面板识别当前手工启动的帕鲁进程；只有用户发起操作后才接管后续生命周期。
6. SteamCMD 使用固定 App ID 和服务端配置中的绝对路径执行。
7. 版本检查是低频自动或手动触发的只读 SteamCMD 任务：先完成 SteamCMD 自身准备，再
   单独比较本机 manifest 与 App `2394010` public 分支 Build ID，不依赖第三方版本服务。
8. 成功备份后按时间与总容量集中清理 Hearth 自身 ZIP；SteamCMD 正式更新按日志进展
   超时，并校验目标 App 的完成标志。

前后端在代码层分离，在部署层合并。这比运行 Node SSR、Redis 和独立数据库更适合单台小型 ECS。

## 没有采用的方案

### PufferPanel 基座

优点是已有用户、控制台和模板系统；缺点是现有 Palworld 配置体验仍需较大幅度定制，接管当前安装也需要额外迁移。项目仅参考其模板模型。

### Pterodactyl/Pelican

适合多租户和大量实例，但 Docker、节点守护进程及配套服务会扩大部署与排障范围。当前两款游戏的场景不采用。

## 安全边界

- 初次部署只监听 Windows 本机回环地址，不修改防火墙。
- 面板密码保存在仅 `SYSTEM` 和 Administrators 可读的文件中。
- 安装器密码是唯一管理员凭据；成员密码使用独立随机盐和
  PBKDF2-SHA256 摘要保存在同一受保护目录，不保存明文。
- 生产管理员密码及新建/修改的成员密码至少 10 个字符；这是最低兼容门槛，文档仍建议
  使用 14 个字符以上的唯一密码或长短语。
- 密码本身就是登录身份，不使用用户名；成员通过自动生成的凭据编号区分。
- 新成员默认只读；管理员可按成员密码授予运行控制、服务端更新、存档备份和
  Palworld 日常玩法参数能力。玩法参数使用后端保守白名单；系统、安全、性能、磁盘、
  未知高级参数和完整 `WorldOption.sav` 始终只允许管理员操作。
- 旧版 `palworld.settings` 权限在加载时降级映射为 `palworld.settings.gameplay`，
  避免升级后继续保留过宽配置能力。
- 成员管理、任务日志、登录审计、安全操作审计和参数审计始终只属于管理员，不能通过成员权限释放。
- 登录审计记录来源 IP、凭据编号、成功状态、原因、攻击等级、连续失败次数和时间，
  不记录输入密码，只包含登录、限流与黑名单拦截事件。
- 安全操作审计使用结构化的操作者和目标字段，覆盖成员凭据创建/修改/删除与 IP 黑白名单
  添加/删除。`actorIp` 是发起管理请求的来源，`targetIp` 或 `targetId` 是被修改的对象；
  密码修改只记录布尔标记，不记录密码、摘要或旧值。
- 参数审计仅在 `PalWorldSettings.ini` 成功保存后，由服务端比较保存前后的结构化值；
  记录操作者、来源 IP、配置版本和真实变更。敏感值只标记“已修改”，不记录前后内容。
- 参数审计使用无数据库 JSONL，保留内存中最近 1000 条；文件达到 5 MiB 后轮转并保留
  一代。写入失败记录到面板运行日志，但不会在配置文件已经成功替换后伪报保存失败。
- 安全操作审计使用独立 `operation-audit.jsonl`，同样保留最近 1000 条并在 5 MiB 时
  轮转一代，避免登录攻击记录挤掉管理员变更证据。
- 登录失败采用按来源状态的指数退避：普通来源从第 5 次连续失败开始按
  1、2、4、8 秒递增，最长 5 分钟；可信设备或白名单来源从第 10 次开始，最长 30 秒。
  成功的密码校验只清除当前来源/设备状态，不会替攻击者清除其他来源状态。
- PBKDF2 校验有两个普通来源并发槽和一个可信来源保留槽，避免请求洪峰让 CPU 和正常
  用户相互拖死。所有状态表、会话表和规则表都有固定上限。
- 登录成功后签发 30 天 HMAC 签名的 `HttpOnly`、`SameSite=Strict` 设备 Cookie；
  它只选择可信限流通道，不能创建会话、不能通过鉴权，也不能替代管理员或成员密码。
- IP 黑名单在密码摘要校验前拒绝；白名单只选择可信限流通道，永不绕过密码。首版只允许
  精确 IPv4/IPv6，拒绝本机、未指定、组播和可信代理地址，降低误封整网或锁死代理风险。
  默认快速黑名单 24 小时、白名单 7 天，最长 365 天，也可由管理员明确设为永久。
- 只有当直接连接地址属于 `trustedProxyCidrs` 时才接受转发头，并从
  `X-Forwarded-For` 右侧向左剥离可信代理；格式异常、超长或跳数过多时回退为直接连接
  地址。默认只信任回环代理。
- 进入 warning/critical 攻击等级时明确写审计；已被限流或黑名单拒绝的重复请求最多
  每分钟写一条，避免攻击者反向撑爆审计文件。登录审计 JSONL 在 5 MiB 时轮转并保留一代。
- JSON API 请求有明确大小上限，只接受单个完整对象，不接受尾随值或超限截断内容。
- Web 页面每次载入都会注销旧浏览器会话并要求重新登录；删除成员，或修改成员密码、
  权限时立即撤销该成员已有会话。
- 不允许前端提交可执行文件路径或任意命令参数。
- 游戏 ID 到进程名、安装目录和 Steam App ID 的映射只来自服务端配置。
- 同一个游戏同时最多运行一个变更任务。
- 运行中的更新和备份必须先通过 Palworld 官方 REST API 保存世界。
- 停止和重启始终先尝试 REST API 安全关闭；REST 不可用且用户在确认框中明确接受
  存档风险时，只允许终止任务创建时捕获的同一 PID 与启动时间对应的 Palworld 进程。
- REST 明确确认无人在线时，安全关闭通知等待最多 5 秒；有人在线或人数查询失败时保留
  `shutdownWaitSeconds`，避免因监控异常误踢玩家。
- 更新前执行保存、优雅停止和关键文件 ZIP 备份。
- 新建 ZIP 始终保留；旧 Hearth ZIP 默认保留 30 天且合计不超过 20 GiB。清理失败只
  写入告警，不把已经成功创建的备份伪报为失败，也不删除未知命名文件。
- 强制停止回退不适用于更新、备份、配置写入或任何其他操作。
- 如果已有 `steamcmd.exe` 正在运行，拒绝并发更新。
- SteamCMD 自身更新、服务端下载与校验共用日志进展监测；默认连续 30 分钟无日志增长
  才终止进程树。干净退出但缺少 App ID `2394010` 成功标志时只自动重试一次，防止
  自更新阶段被误判为服务端更新完成。
- 版本检查与其他游戏任务共用串行任务锁；手动触发需要“更新服务端”权限。启动后 30 秒
  尝试首次检查，之后每 15 分钟判断，成功结果有效 6 小时，失败重试至少间隔 1 小时。
  繁忙或已有 SteamCMD 时跳过。SteamCMD 自身版本不展示也不参与结论；检查结果不落盘。
  准备阶段沿用 SteamCMD 无日志进展超时，自更新持续产生日志时不会被固定总时长打断。
- `WorldOption.sav` 与 `PalWorldSettings.ini` 分源读取和保存，不自动合并或跨文件同步。
- 重复参数显示来源冲突；保存请求只包含用户明确修改的字段，并检查源文件版本。
- `WorldOption.sav` 写入前执行完整语义往返校验；浮点数按数值比较，避免 `5` 与 `5.0`
  的等价格式被误报为失败。
- 配置写入使用“临时文件 + 校验 + 原子替换”。
- `PalWorldSettings.ini` 的结构化响应会脱敏密码；成员响应还会移除原始 INI 和所有非
  白名单参数。`WorldOption.sav` 原始文档仅管理员可读，前端解析后掩码展示。两种来源
  的密码未显式输入时都不会写回。
- Palworld REST API 固定使用 `127.0.0.1`，不允许前端控制目标地址。

## 当前验收标准

- 空闲状态不持续轮询 SteamCMD，只按六小时成功结果有效期低频检查服务端版本。
- 版本检查能区分“尚未检查、检查中、最新、有新版本、暂不可用”，且不会修改服务端文件
  或把 SteamCMD 自身更新误报为 Palworld 更新。
- 登录后能查看 Palworld 和主机真实状态。
- 更新、重启等操作有二次确认与可追踪任务记录。
- 长任务显示阶段、最近细节和 0–100% 进度。
- 备份保留同时受时间和总容量约束，且不会清理新备份或未知文件。
- SteamCMD 自更新不会被固定总时长误杀；真实无进展会超时并留下可重试错误。
- 管理员能添加、修改和删除成员密码，按密码分配能力，并查看登录、安全操作与参数审计。
- 无对应能力的成员无法调用进程操作或配置 API；所有成员都无法访问任务日志、成员管理
  和三类审计 API。
- 获得玩法参数权限的成员只能读取和修改服务端白名单中的 INI 参数；不能读取原始 INI、
  `WorldOption.sav` 或系统/安全参数。
- Palworld 配置支持结构化编辑和原始配置兜底。
- 不识别的 Palworld 参数在保存后仍被保留。
- 服务器新版本加入默认配置参数后，无需升级面板即可出现在“其他 1.0 参数”中。
- 前端可以在手机宽度完成常用操作。
- 总览问候语使用访问者浏览器本地时间，并在页面停留期间自动刷新。
- `go test ./...`、前端类型检查和 Windows amd64 交叉编译通过。
